# Eval-stack fixes, 2026-09-11

Revision base: `54bb470` (changes left uncommitted). Three breaks fixed and
verified live with `z-ai/glm-5.3-flash`.

## 1. Treatment labels made resolvable

`internal/cli/mvp_matched.go`: `armTreatment` returned `memory_off` /
`memory_on`, which `splice.ResolveTreatment` rejects, so every `eval mvp`,
`eval families`, and campaign attempt failed before its provider call.
It now returns a valid name: an ambient `SPLICE_TREATMENT` canonical name when
one resolves, else `cold` for a cold arm and `full` for every other arm.

`internal/cli/mvp_campaign.go`: `armTreatmentFor` now returns the arm table's
explicit treatment (`cold` or `full`) instead of recomputing an invalid label
from the arm name.

Tests: `TestArmTreatmentReturnsResolvableNames` (new) and
`TestCampaignArmTreatmentLabelsMatchChildOptions` (updated to assert the name
resolves and realizes the arm's `--memory` flag).

Live check: `eval families` on one family, rollouts 1, now runs. Cold 0/1
success at 17,617 tokens; warm 1/1 success at 11,127 tokens.

## 2. Generation attribution restored in the live ledger

`internal/splice/run.go`: the writer's first round is a context handshake that
issues no provider request, so the D2 loop labeled the first real provider
round `expansion`/1 and the live ledger carried no `generation` record. The
loop now counts provider requests through the attributed-usage closure and
labels the first provider-bearing round `generation` (or `repair` for a repair
re-entry) at round 0; later provider-bearing rounds are `expansion`/1+.

Test: `TestRunStageWithContextLabelsFirstProviderRoundGeneration` (new) uses a
handshake stage with no round-0 usage and asserts the first attributed record
is `generation`/0.

Live check: ledger attempt sources are now cold `generation`/0 twice and warm
`generation`/0 three times plus `repair`/0 once. No `expansion` appeared
because no model-driven context round was requested in that run.

## 3. Eval token reading made symmetric

`internal/cli/pair_eval.go`: cold tokens came from stream-json usage and warm
tokens from the trace, so the two arms were not comparable. Both arms now read
the authoritative request ledger from the run's final stream-json event
(`parsePipelineResultTokens`), with stream-json as the symmetric fallback when
no final event exists. The trace is read only for interventions.

`internal/eval/harness.go`, `internal/eval/report.go`: the result carries
`TokenSource`, each pair carries `cold_token_source` / `warm_token_source`, and
the Markdown report prints `token source: cold=... warm=...` plus a loud
`TOKEN SOURCE MISMATCH` warning when the two arms differ.

Test: `TestParsePipelineResultTokensReadsLedgerTotals` (new).

Live check: the pe report shows `token source: cold=ledger warm=ledger`.
